# Release: mxcli v0.29.0

*October 30, 2026*

v0.29.0 is about **writing what your project's own Mendix version stores, and committing it the way Studio Pro does**. A statement your Mendix 9 or 10 project can't store is now refused at check time, before it can leave you with a project Studio Pro won't open. And a team that commits with plain git can keep its history in the shape Studio Pro expects.

## What's new

**Commit the way Studio Pro does.** Studio Pro's *Commit* does more than `git commit`: it keeps the contents hashes in step, leaves out the files a Mendix repository never ships, and attaches the `mx_metadata` note it uses for its version check and history. `mxcli git commit` does all of that in one line:

```bash
mxcli git commit -m "Add order approval" -p app.mpr --push
```

`--push` pushes the note along with the branch. `--dry-run` shows what would be committed without writing anything. The commit is refused while Studio Pro has the project open, or while a merge is unresolved.

**Audit a repository.** `mxcli git doctor` reports what a plain-git history has drifted on: missing local git config, an SSH remote Studio Pro can't use, commits without a note, and notes Studio Pro can't read. It exits 1 while an issue remains, so it can gate CI. `--fix` repairs them.

**Your Mendix version decides what gets written.** mxcli now knows which element types and property shapes each Mendix version has, measured against Studio Pro. Workflows, aggregates, constant overrides and `$currentObject` arguments are written in the shape Mendix 9 and early 10.x expect. Before, they were refused or left the project unloadable. A statement the version can't store, such as `notify workflow` on 9.x or a loop feature from a later release, now fails `check -p` with MDL-VERSION01 and names the clause. `alter microflow` is gated the same way as `create`.

**Workflows say more.** A user task takes a `task name`. Workflow and task texts take template parameters (`display 'Approval for {1}' with ({1} = $WorkflowContext/Title)`), and a timer boundary event takes a caption. A non-interrupting timer can repeat, with `repeat every 1 day at most 3 times` after its delay.

A new warning, MDL-WF20, catches a user task whose page has no way to complete one of its outcomes. That mistake passes the build and leaves every instance waiting at the task.

**Edit inside a loop.** `alter microflow` and `create or modify` now insert, drop or move an activity inside a loop body, where they used to refuse. If you want the old behaviour, `replace body of <loop>` replaces just the body, keeping the loop's IDs.

**Fewer settings lost on a rewrite.** A page's own design properties, a native text style, a tab page's badge, a text area's line count, a layout's sidebar mode, a read-only data view, and return value mappings on a button's flow call now survive describe → exec. You can also write them in MDL. Java actions get an `extra code` clause. And `alter app security (AdminPassword: '…')` clears CE0129 without opening Studio Pro.

**Faster on large projects.** On an MPR v2 app with 4,753 units, `show modules` used to open 4,511 files and `describe page` 3,176, on every run. Each command now opens only the files it needs. A catalog refresh after a save reads one file or none, and a source-index rebuild describes only what changed.

**The debugger works end to end.** `mxcli debug break` sets the breakpoint, `continue` resumes the paused flow, and `inspect` prints a String or enumeration value. When the runtime refuses a request, the command now fails with the runtime's reason instead of reporting success.

**`check` catches more of what `mx check` would refuse.** Examples are a property the widget doesn't take (`Caption:` on a text box), a member the entity lacks, a duplicate member name on an inheritance chain, an unknown `[%UserRole_X%]`, and Java action types that can't be stored. Renames and moves of constants, enumerations and attributes now update the expressions and XPath constraints that refer to them. `diff-local` also shows every change, settings and grants included.

## Upgrading

Download the `v0.29.0` binary for your platform from the [release page](https://github.com/mendixlabs/mxcli/releases/tag/v0.29.0):

```bash
curl -fsSL -o mxcli \
  https://github.com/mendixlabs/mxcli/releases/download/v0.29.0/mxcli-linux-amd64
chmod +x mxcli && sudo mv mxcli /usr/local/bin/
```

Then refresh a project's skills, commands and the companion mod with `mxcli init --sync-skills`.

Behaviour changes worth knowing:

- `docker check` now checks the project as stored. Before, it ran `mx update-widgets` on a copy first, so a project with stale widgets got "0 errors" and was then refused by `run --local` and the build. Stale widgets now fail the check, and each CE0463 that `mxcli fix widgets` would clear is labelled as such.
- `check -p` refuses more: anything your project's Mendix version can't store, and several mistakes it used to pass that `mx check` then rejected. A script that passed before may need a fix, but it would not have built.
